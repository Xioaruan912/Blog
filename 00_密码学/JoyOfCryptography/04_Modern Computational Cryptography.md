这里我们开始讨论现代密码如何界定安全

之前 OTP 和 SS 我们都说明了 是通过两个库 比较输出的概率，<span style="color:#FF0000;">要求这两个概率不能有任何区别，否则就是不安全的</span>

> 思考一个问题，如果密码方案可以被攻破，但是需要你使用超过你身价的资金，那你会不会选择攻破？又或者说需要花费 1000 年的事件，你会不会选择攻破

但是我们之前讨论的安全内容，和花费还有运行时间完全无关，我们之前只考虑算法在面对敌手设计的时候 输出的概率差值

所以如果按照之前的来说，即使 1000 年以后被破解了，那么这两个库依旧是不安全的，也就是无法互换的

如果一个加密方案允许这种攻击，那么根据之前的安全性定义，它就会被认定为不安全

> 思考另一个问题，如果密码方案可以被攻破，但是最好的攻击概率只有非常非常非常非常低

我们可以类比，这里获胜的概率其实和连续中 100 次彩票一样，那么其实你并不会担心被攻破，因为这个发生的概率几乎不可能，但是按照之前的界定

还是存在微小概率，使得两个库的输出有差距，从而不可互相交换，所以不安全

如果一个加密方案允许这种攻击，那么根据之前的安全性定义，它就会被认定为不安全

那么到这里其实就讨论了一个内容：**<span style="color:#FF0000;">之前的安全太过于严格，只关心了攻击概率是否完全不同，但是不关心 攻击需要花费多少时间，以及攻击成功的概率到底有多大</span>**

## 现代可证明安全性的方法

依旧沿用 第二章的 real or rand 和 left or right 

但是我们会<span style="color:#FF0000;">忽略需要极高的开销和极低的概率的获胜情况</span>

也就是我们希望从 “没有敌手可以攻击成功，即使理论上也不行” 转移到

“任何敌手如果需要攻击成功，那么就需要花费极大的代价以极低的概率获胜”

那么下面我们会具体说明到底什么是极大什么是极小

# 4.2. The asymptotic approach to provable security

上面我们大概说明了 如果一个花费超过 128 成功概率为 -64 的密码方案，可以看作是安全的

这个是具体方法回答的问题——为了达到足够的安全性，我的密钥应该有多大？

但是这种表述会导致证明安全过程非常困难，因为我们无法说明密钥在这个情况下到底是不是真的安全

那么这个时候就需要渐进证明，它允许我们作出更加定性【不关注具体数值，而是关注整体性质】的、非此即彼【在渐近安全性定义下，判断方案是否满足某个安全性质】的安全性判断，但代价是失去一部分定量精度

**渐进**：表示这个行为在算法的极限是哪里——也就是<span style="color:#FF0000;">密钥如果趋于无限大，算法会怎么样</span>

**渐近安全性关注的是随着密钥长度不断增加，<span style="color:#FF0000;">算法的整体表现</span>，而不是某个固定密钥长度下的具体数值**

我们可以使用 大 O 来测量，比如我们需要测量一个 n^2 的多项式次数的运算，我们使用大 O，只要认为他需要 O(n ^2)的步骤即可，虽然损失了精度，但是节省了很多内容

所以 Concrete Approach 追求具体、精确的安全保证，而 Asymptotic Approach 则使用渐近分析，观察算法在密钥不断增大的时候产生的效果

> 大 O

如果有一个常数 c 使得除了有限的 n 外，其他都满足 f(n)<= c*g(n)

那么我们就认为 f(n) in O(g(n))

也就是算法 f(n) 的运行时间不会比 g(n) 的某个常数倍增长得更快

也就是说 g(n) 在乘上某个常数的时候 速度会比 f(n)快

## 4.2.1. Polynomial running time

这个是渐进方法的核心内容，<span style="color:#FF0000;">多项式时间</span>

在渐进式证明中，我们会让敌手运行在多项式时间内

> 多项式时间的定义

如果有一个多项式 p，还有一个算法 A，A 运行步骤最多达到 O(p(n)) 级别，n 是输入，那么这个 A 就是多项式时间算法

密码学一般把安全参数和运行时间作为测量，一般情况下安全参数是密钥的长度 *λ*

并且我们可以假设 所有的算法和库都可以访问全局变量 *λ*

- 多项式还有一个特性：<span style="color:#FF0000;">如果一个多项式程序运行一个多项式子程序，那么可以组合成一个完整的多项式算法</span>

## 4.2.2. Negligible probabilities

这里进入可忽略函数

上面我们学习多项式时间，可以让我们忽略算法具体到底运行多少具体时间，只要知道多项式时间，即可估算出运行时间

那么我们可以基于多项式时间对算法继续分类，不同大 O 可以分类为一起

这里渐进式分析告诉我们  一个函数以多快的速度趋向无穷大。

在密码学中 我们使用 **渐进分析描述 随着安全参数的增加，攻击成功概率趋于 0 的速度有多快**

如果速度很快，那么我们就认为攻击成功是不可能的事情，下面看两个例子理解：

> 一个密码算法发生灾难的概率为 1/λ^2，那么趋向于 0 的速度快不快？

比如有一个攻击场景，敌手可以按照 λ^2 机会 去触发灾难 因为 λ^2 也是多项式，所以其实敌手可以按照一个很好的概率得到灾难场景的，所以 1/λ ^2 的倾向于 0 的速度并不快

> 一个密码算法发生灾难的概率为 1/2^λ，那么趋向于 0 的速度快不快？

依旧 敌手有 λ^2 机会  去触发灾难  因为 λ^2 是多项式，那么成功的概率是 λ^2/2 ^λ 可以发现

趋向于 0 的速度是非常快的

所以如果一个有问题的方案被破解的概率是 1/2 ^λ 那么我们认为破解他是不可能的事情

## 不可忽略函数定义

我们要求一个安全的密码，敌手获胜的概率一定小于任意的多项式的倒数

> 如果 f 是一个可忽略函数 比任何多项式倒数都小

- 有一个阈值，只要超过了这个阈值，f 就会一直比任意多项式小
- 1/f() 的增长速度足够快，能够在渐近意义下超过任意多项式的增长速度，反过来 f 下降的速度非常快，能够渐进中超过任意多项式的倒数

我们一般使用 q(λ)/2^λ 来表示不可忽略概率

这里我们基于上面的渐进式 引入不可区分性

之前我们说过两个库 <span style="color:#FF0000;">如果输出的概率相同，那么就具有可交换性</span>，这里安全严格，那么我们转化为渐进呢？

在现代渐进式证明中，我们说，<span style="color:#FF0000;">两个库如果在多项式敌手中，输出的概率都是可忽略接近的，那么这两个库就是具有不可区分性的</span>

> Indistinguishability

这里正式定义一下

可以发现，这里得到的优势是 敌手访问 L1 L2 的差值

如果这个差值是可忽略的 那么我们就认为是这两个库是不可区分的，符号记作 ` L1≊L2`

## 不可区分性的特性

我们还会借助不可区分性的特性来证明安全，那么这里介绍一下

![image-20261024114517113](https://raw.githubusercontent.com/Xioaruan912/pic/main/20261024114517150.png)

1. 如果两个库具有<span style="color:#FF0000;">可交换那么就具有不可区分性</span>，这个很好理解，因为之前是要求两个库是具有完全相同概率，然后现在是可忽略
2. 这里需要借助两个子定理理解
   1. f 和 g 都是可忽略，那么 f+g 也是可忽略
   2. 绝对值不等式

![image-20261024114638599](https://raw.githubusercontent.com/Xioaruan912/pic/main/20261024114638621.png)

那么就很简单了 我们套用定义，转化为绝对值不等式

因为说过了 p1 p2 是不可区分的 p2 p3 是不可区分的

两个不可区分叠加是不可区分的，从而说明了传递性

这里的 p 是敌手区分的优势

3. 和之前证明的一样，调用不可区分程序，依旧是不可区分的

## 基于不可区分性的混合证明

我们之前学习了基于可交换的混合证明，其实就是链式证明，只要每个都是可交换的，就可以说明最开始和最后是可交换的

但是这里需要说明的是

1. 如果是<span style="color:#FF0000;">常数项库的叠加</span>，产生的可忽略概率叠加后<span style="color:#FF0000;">也是可忽略的</span>
2. 如果库依赖于安全参数，渐进式证明又要求<span style="color:#FF0000;">安全参数趋向无穷</span>，那么这个时候<span style="color:#FF0000;">有可能导致不可忽略的产生</span>

这里安全参数的增加可能会导致敌手访问次数的增加，从而导致敌手成功区分的概率增加，我们需要严谨分析这个内容

这里说一个粗糙的声明

> 如果 L0≊L1≊……≊Lq = L *，其中 q 是一个安全参数的多项式，那么就可以证明 L0≊L *

可以看到 最后一个是 可交换，而不是不可区分

但是这里有一个问题，这里我们探索的是固定了 i 然后去考虑随着安全参数不断增大后库的渐进行为

什么意思呢？ 也就是我们讨论的不可区分性 `L0≊L1`

**是库 0 和库 1 在安全参数不断变大的情况下，具有不可区分性**

> 安全参数 决定密码方案的规模，i 决定我们比较哪两个相邻的混合

那么即使安全参数变化，我们依旧分析的是 固定的 i，因为我们的 q 是固定的，是常数项的

但是现在我们说 敌手可以控制 q，产生基于安全参数的访问次数 q'，那么我们之前证明的 q 是具有不可区分性的，<span style="color:#FF0000;">无法讨论大于 q 的情况下 </span>是不是具有不可区分性的，因为 **q 是固定的**

- 每个固定位置的不可区分性
- 随着安全 参数增加而出现的位置的不可区分性

这两个是无法基于声明直接推出的，所以下面我们需要一个更加细节的声明，要求敌手可以控制 q 和 i，依旧保证不可区分性

> L *和 L0…..是多项式时间库，如果满足下面内容就说明 L * 和 Li 具有不可区分性

- 混合变为多项式数量，这个多项式数量是敌手决定的

也就是说敌手看到的混合数量可以自己定，但是看到的输出概率都是一样的

- 连续的 i 和 i-1 都是不可区分性的，即使这里的 i 是敌手自己选择的

这里把固定的 i 转化为一个变量，这个变量基于敌手的选择

只要满足上面<span style="color:#FF0000;">两个固定转为变量的内容</span>依旧满足不可区分性，那么就说明 **L * 和 L0 具有不可区分性**

到这里就结束了，其实最简单的理解就是，我们把我们有限的转化为敌手无约束的控制，说明即使敌手可以控制访问次数和混合个数，依旧是不可区分性的

## 使用 Bad Event 证明不可区分性

3. L1 L2 具有相同的代码，除了<span style="color:#FF0000;">执行完 Bad 后会产生不同的执行代码</span>

## 证明坏事情和不可区分性的概率

这里我们需要使用到概率论的内容 所以我们简单介绍一下

> 基本概率

Y 是一个事情，Y~是对立事件

Pr [Y] + Pr [Y~] = 1

> 条件概率

Pr [X|Y] 的意思是 Y 情况发生下，X 发生的概率

我们具有下面等式

Pr [X|Y] = Pr [X ^ Y] / Pr [Y]

> 全概率公式

如果我们需要知道 X 发生的所有概率 可以使用下面表达

Pr [X] = Pr [X|Y] Pr [Y] + Pr [X|Y ~] Pr [Y ~]

这里我们回顾了概率论简单内容 下面开始证明

不可区分性优势 <= 坏事情发生概率

对于第 i 次执行，输出 distinct 的概率是 1-(i-1)/N

因为前面有 i-1 个值 N 是全部值的集合，(i-1)/N 就是会输出相同的概率  1-就得到了不同的概率
